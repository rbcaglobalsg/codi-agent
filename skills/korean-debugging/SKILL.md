# 한국어 체계적 디버깅

## 트리거
버그, 에러, debug, "왜 안돼", "고쳐줘", 에러 분석, 디버깅

## 4단계 프로세스

### 1단계: 이해 (Understand)
- 에러 메시지 전문 읽기
- 어떤 상황에서 발생했는지 재현
- 관련 코드 파일 전체 읽기 (일부만 보지 않음)
- 최근 변경 사항 확인 (git log, git diff)

### 2단계: 근본 원인 (Root Cause)
- 증상 ≠ 원인. 증상을 고치지 말고 원인을 고칠 것
- 로그/스택트레이스에서 에러 발생 지점 추적
- 가설 수립: "X 때문에 Y가 발생한 것 같다"
- 가설 검증: 로그 추가, print, breakpoint

### 3단계: 수정 (Fix)
- 근본 원인에 대한 수정
- 같은 버그 클래스의 형제 코드도 확인
- 수정 후 테스트 추가 (회귀 방지)

### 4단계: 검증 (Verify)
- 에러 재현 시나리오로 확인
- 기존 테스트 전체 통과 확인
- 부작용 없는지 확인

## 자주 발생하는 한국 개발 환경 에러
- **인코딩**: UTF-8/EUC-KR 혼용 문제
- **시간대**: Asia/Seoul vs UTC
- **한글 폰트**: 빌드 시 한글 폰트 누락
- **API 인증**: 한국 서비스 API 인증 방식 (네이버/카카오/토스)
- **CORS**: 한국 도메인 CORS 설정

## 금지
- 에러 메시지 안 읽고 추측
- 증상만 고치고 원인 방치
- "이렇게 하면 되지 않을까" 실험적 수정
- 로그 안 보고 코드만 수정
